# MFY — стандарт языка

**Версия 1.0 (черновик) · 2 ноября 2026**

MFY — учебный императивный язык со строгой статической типизацией. Название составлено из первых букв имён команды. Исходные файлы имеют расширение `.mfy`.

Этот документ — стандарт языка: он определяет, какие программы корректны и что они делают. Если реализация расходится со стандартом, исправляется реализация (или сначала явно меняется стандарт). Как устроен наш интерпретатор — этапы, представление данных, команды, форматы вывода, — описано отдельно, в [implement.md](implement.md).

```mfy
def fact(n: int): int {
    if n <= 1 { return 1; }
    return n * fact(n - 1);
}

let a: int[] = [4, 2, 8];
let sum: int = 0;
for (let i: int = 0; i < length(a); ++i) {
    if a[i] == 2 { continue; }
    sum = sum + a[i];
}
print sum;       // 12
print fact(5);   // 120
```

Главное о языке:

- типы `int`, `real`, `bool`, `str`, `void`, массивы, структуры и указатели; все типы известны до запуска;
- `;` завершает инструкцию, `{}` образует блок со своей областью видимости;
- присваивание `=` — инструкция, а не выражение, поэтому `a = b = 10` запрещено;
- модификаторы `p` («указатель на») и `c` («константный»), взятие адреса `&x`, разыменование `$p`, поле через указатель `p->f`;
- тернарный оператор `cond -> a | b`, только префиксные `++x` и `--x`;
- значения всегда копируются, массивы и структуры — целиком (глубоко).

## 1. Обозначения

Грамматика записана в EBNF:

| Запись | Значение |
|---|---|
| `a = b ;` | правило: `a` определяется как `b` |
| `"let"` | лексема, записанная буквально |
| `IDENT` | класс лексем (§2) |
| `x \| y` | альтернатива |
| `[ x ]` | необязательная часть |
| `{ x }` | повторение 0 и более раз |
| `( x )` | группировка |

Требования к операндам в описаниях операторов и инструкций:

| Обозначение | Что можно подставить |
|---|---|
| **R** | любое выражение; используется его значение. lvalue тоже подходит: его значение неявно читается |
| **L** | только lvalue (изменяемое или нет) |
| **ML** | только изменяемое lvalue |

**Ошибка проверки** обнаруживается до запуска программы. **Ошибка выполнения** возникает во время работы программы. Обе сообщаются с позицией в исходном тексте (§12).

## 2. Лексика

### 2.1 Исходный текст

- Файл в кодировке UTF-8. Символы вне ASCII допускаются только внутри строковых литералов и комментариев.
- Перевод строки — `\n` или `\r\n` (считается одним переводом).

### 2.2 Пробелы, отступы и комментарии

- Пробельные символы: пробел, табуляция, `\r`, `\n`. Они разделяют лексемы и больше ничего не значат. Пробелы и табуляции в начале строки игнорируются, отступы не значимы.
- Инструкцию завершает `;`, а не конец строки. Одна инструкция может занимать несколько строк, в одной строке может быть несколько инструкций.
- Однострочный комментарий: от `//` до конца строки.
- Многострочный комментарий: `/* ... */`. Вложенность не поддерживается: комментарий закрывает первая `*/`. Незакрытый комментарий — лексическая ошибка с позицией его начала.
- Внутри строкового литерала `//` и `/*` — обычные символы.
- **Обязательные пробелы.**
  - Сразу после ключевых слов `if`, `while`, `for` должен стоять пробельный символ. `if (x > 0)` и `if x > 0` корректны, `if(x > 0)` — лексическая ошибка.
  - Лексема `->` имеет два значения, и их различает пробел перед ней. Если `->` отделена от предыдущей лексемы пробелом, переводом строки или комментарием, это тернарный оператор: `x > 0 -> 1 | 2`. Если стоит вплотную — доступ к полю через указатель: `node->next`. Поэтому `x>0-> 1 | 2` — синтаксическая ошибка: после `->` ожидается имя поля. В грамматике (§13) эти лексемы обозначены `COND_ARROW` и `PTR_ARROW`.

### 2.3 Правило самой длинной лексемы

Текст делится на лексемы слева направо: из текущей позиции всегда берётся самая длинная лексема, даже если после неё разбор продолжить не удастся. При равной длине приоритет такой: ключевое слово, затем `MODWORD`, затем `IDENT`.

| Текст | Лексемы | Комментарий |
|---|---|---|
| `++x` | `++` `x` | инкремент |
| `- -x` | `-` `-` `x` | двойной унарный минус |
| `a==b` | `a` `==` `b` | |
| `a<=b` | `a` `<=` `b` | |
| `x:=1` | `x` `:=` `1` | |
| `c -> a \| b` | `c` `->` `a` `\|` `b` | тернарный оператор: перед `->` пробел |
| `node->next` | `node` `->` `next` | поле через указатель: `->` вплотную |
| `i++` | `i` `++` | далее синтаксическая ошибка: постфиксного `++` нет |
| `format` | `format` | идентификатор, а не `for` + `mat` |
| `integer` | `integer` | идентификатор, а не `int` + `eger` |
| `1.5` | `1.5` | вещественный литерал |
| `1.` | `1` `.` | после точки нет цифры, откат к `1` |
| `1..2` | `1` `.` `.` `2` | |
| `1e5` | `1e5` | вещественный литерал |
| `1e` | `1` `e` | после `e` нет цифры, откат к `1` |
| `2.5e-3` | `2.5e-3` | |

### 2.4 Идентификаторы

```text
IDENT = [a-zA-Z_][a-zA-Z_0-9]*
```

Регистр различается: `Sum` и `sum` — разные имена. Идентификаторы называют переменные, функции, типы-структуры и поля.

**`MODWORD`** — особый вид идентификатора: слово только из строчных букв `p` и `c` (`p`, `c`, `cp`, `pp`, `pcpc`, …). В позиции типа (после `:`) это модификатор (§4.2), во всех остальных местах — обычное имя. Поэтому переменная или функция может называться `p` или `c`, а структура — нет.

### 2.5 Ключевые слова и зарезервированные имена

| Группа | Слова |
|---|---|
| Объявления | `let` `def` `type` |
| Управление | `if` `else` `while` `for` `break` `continue` `return` |
| Вывод | `print` |
| Логические операторы | `and` `or` `not` |
| Литералы | `true` `false` `null` |
| Типы | `int` `real` `bool` `str` `void` |
| Зарезервированы для расширений (§14) | `reactive` `include` `enum` |

Ключевое слово нельзя использовать как имя. Это синтаксическая ошибка:

```mfy
let for: int = 1;      // синтаксическая ошибка: for — ключевое слово
```

Имена встроенных функций `input`, `length`, `assert` (и `random` из §14) — не ключевые слова, но объявить переменную, функцию или тип с таким именем нельзя. Это ошибка проверки.

### 2.6 Литералы

**Целый** (`INT_LIT`): `[0-9]+`, десятичная запись. Значение должно помещаться в `int`, то есть не превышать 9223372036854775807, иначе это лексическая ошибка. Знака у литерала нет: `-5` — это унарный минус, применённый к `5`. Ведущие нули допустимы и не означают восьмеричную запись: `007` равно 7. Минимальное значение `int` записывается как `-9223372036854775807 - 1`.

**Вещественный** (`REAL_LIT`):

```text
REAL_LIT = [0-9]+ "." [0-9]+ ( [eE] [+-]? [0-9]+ )?
         | [0-9]+ [eE] [+-]? [0-9]+
```

Цифры по обе стороны точки обязательны: `1.5`, `0.5`, `3.0e8`, `2e-3`. Записи `1.` и `.5` вещественными литералами не являются. Значение — ближайшее `double`. Если число не помещается в `double` (`1e999`), это лексическая ошибка.

**Строковый** (`STR_LIT`): текст в двойных кавычках на одной строке. Escape-последовательности:

| Запись | Символ |
|---|---|
| `\n` | перевод строки |
| `\t` | табуляция |
| `\r` | возврат каретки |
| `\\` | обратная косая черта |
| `\"` | двойная кавычка |

Любая другая последовательность `\x` — лексическая ошибка. Перевод строки или конец файла до закрывающей кавычки — лексическая ошибка «незакрытый строковый литерал».

**Логические**: `true`, `false`. **Нулевой указатель**: `null`.

### 2.7 Операторы и разделители

| Лексема | Назначение |
|---|---|
| `+` `-` `*` `/` `%` | арифметика |
| `++` `--` | префиксные инкремент и декремент |
| `=` | присваивание (инструкция) |
| `:=` | присваивание-выражение |
| `==` `!=` | равенство |
| `<` `<=` `>` `>=` | сравнение |
| `->` с пробелом перед ним, `\|` | тернарный оператор |
| `->` вплотную к предыдущей лексеме | доступ к полю через указатель |
| `$` | разыменование |
| `&` | взятие адреса |
| `.` | доступ к полю |
| `(` `)` | приоритет, вызов, заголовок `for` |
| `[` `]` | массивы, индексация |
| `{` `}` | блок, тело структуры |
| `,` `;` `:` | разделители |

Одиночный `!` не является лексемой (допустим только в `!=`). Для логического «не» используется `not`.

### 2.8 Лексические ошибки

| Ситуация | Пример |
|---|---|
| Недопустимый символ | `let x: int = 5 # 3;`, одиночный `!`, кириллица вне строки |
| Незакрытый строковый литерал | `print "hi;` |
| Неизвестная escape-последовательность | `"a\q"` |
| Незакрытый многострочный комментарий | `/* ...` до конца файла |
| Целый литерал вне диапазона | `9223372036854775808` |
| Вещественный литерал вне диапазона | `1e999` |
| Нет пробела после `if`, `while`, `for` | `if(x)`, `while(true)` |

## 3. Виды конструкций

Каждая конструкция MFY относится ровно к одному виду:

```text
Конструкция MFY
├── 1. Выражение (expression): имеет статический тип и значение
│   ├── 1.1 lvalue: обозначает объект в памяти
│   │   ├── изменяемое lvalue
│   │   └── неизменяемое lvalue (объект с модификатором c)
│   └── 1.2 rvalue: временное значение без своего места в памяти
│       └── void-выражение: вызов функции без результата (частный случай)
├── 2. Инструкция (statement): выполняется ради эффекта, значения не имеет
│   ├── 2.1 объявление переменной: let
│   ├── 2.2 простые: присваивание =, инструкция-выражение, print, return, break, continue
│   └── 2.3 составные: блок {}, if, while, for
├── 3. Определение (definition): только на верхнем уровне программы — def, type
└── 4. Описатель типа (type specifier): стоит после «:», не вычисляется
```

### 3.1 Выражение

У каждого выражения есть **статический тип** (известен до запуска) и **категория**: lvalue или rvalue.

**lvalue** обозначает объект — ячейку памяти: переменную, элемент массива, поле структуры или объект под указателем. У lvalue можно взять адрес (`&`). Изменяемое lvalue может стоять слева от `=` и `:=` и быть операндом `++`/`--`.

- **Изменяемое lvalue** — объект без модификатора `c`.
- **Неизменяемое lvalue** — объект, тип которого содержит `c` на верхнем уровне: константная переменная, элемент массива константных элементов, поле константной структуры, `$p` при `p: pc T`.

**rvalue** — временное значение, не связанное с объектом: литерал, результат арифметики или сравнения, вызов функции, преобразование типа, литерал массива, `&x`, `a := b`.

**void-выражение** — вызов функции, которая ничего не возвращает. Значения у него нет, поэтому оно допустимо только как инструкция-выражение (§7.3) и не может быть операндом.

**Чтение lvalue.** Там, где требуется значение (R), можно подставить lvalue: его текущее значение копируется. Обратного преобразования нет: rvalue никогда не становится lvalue.

Категория каждого вида выражений:

| Выражение | Категория |
|---|---|
| имя переменной `x` | lvalue; изменяемое, если в типе `x` нет верхнего `c` |
| `a[i]` | lvalue, если `a` — lvalue; иначе rvalue |
| `s.f` | lvalue, если `s` — lvalue; иначе rvalue |
| `$p` | всегда lvalue |
| `p->f` | всегда lvalue |
| `++x`, `--x` | lvalue (тот же объект, что `x`) |
| `(e)` | та же, что у `e` |
| `c -> a \| b` | lvalue, если `a` и `b` — lvalue одного и того же типа; иначе rvalue |
| вызов функции без результата | void-выражение |
| всё остальное | rvalue |

### 3.2 Инструкция

Инструкция выполняется ради эффекта: у неё нет ни типа, ни значения, и она не может быть операндом. Инструкции стоят на верхнем уровне программы или внутри блока. Объявление `let`, присваивание и инструкция-выражение могут также стоять в заголовке `for` (§7.8).

Поэтому присваивание нельзя вложить в выражение:

```mfy
x = y = 10;        // синтаксическая ошибка: после 'x = y' ожидается ';'
if x = 5 { }       // синтаксическая ошибка: '=' не может стоять внутри условия
```

Для присваивания внутри выражения есть отдельный оператор `:=` (§6.11).

### 3.3 Определение

`def` (§8) и `type` (§4.4) стоят только на верхнем уровне программы. Определения не выполняются: они вводят имя, которое видно во всей программе, в том числе выше места определения. Определение внутри блока или функции — синтаксическая ошибка.

### 3.4 Описатель типа

Описатель типа стоит после `:` в `let`, в параметрах, в возвращаемом типе функции и в полях структуры. Это не выражение: в `let x: int = 5;` слово `int` — описатель, а в выражении `int(y)` — оператор преобразования.

## 4. Типы

### 4.1 Базовые типы

| Тип | Значения | Значение по умолчанию |
|---|---|---|
| `int` | целые со знаком, 64 бита: от −2⁶³ до 2⁶³ − 1 | `0` |
| `real` | числа двойной точности IEEE 754 (binary64) | `0.0` |
| `bool` | `true`, `false` | `false` |
| `str` | последовательность байтов любой длины | `""` |
| `void` | значений нет; только возвращаемый тип функции | — |

Кроме базовых есть указатели (§4.2), массивы (§4.3) и структуры (§4.4). Полная запись типа:

```text
type_spec = [ MODWORD ] base_type [ dims ] ;
```

### 4.2 Модификаторы `p` и `c`

Модификатор — слово из букв `p` и `c`, которое пишется перед именем типа через пробел. Читается слева направо: каждая `c` — «константный», каждая `p` — «указатель на», в конце — базовый тип.

| MFY | Читается | Аналог в C++ |
|---|---|---|
| `T` | T | `T` |
| `c T` | константный T | `const T` |
| `p T` | указатель на T | `T*` |
| `pc T` | указатель на константный T | `const T*` |
| `cp T` | константный указатель на T | `T* const` |
| `cpc T` | константный указатель на константный T | `const T* const` |
| `pp T` | указатель на указатель на T | `T**` |
| `pcp T` | указатель на константный указатель на T | `T* const*` |
| `ppc T` | указатель на указатель на константный T | `const T**` |
| `cpcpc T` | константный указатель на константный указатель на константный T | `const T* const* const` |

Правила:

1. Не более двух `p`: `ppp int` и глубже — ошибка проверки «указатели глубже двух уровней запрещены».
2. Две `c` подряд (`cc`, `pcc`) — ошибка проверки.
3. Итого допустимы ровно слова, подходящие под `c?(pc?){0,2}` (кроме пустого) — 13 вариантов.
4. Модификатор пишется одним словом: `p p int` — синтаксическая ошибка.
5. С `void` модификаторы не сочетаются.
6. У массивов модификатор относится к типу элемента (§4.3). Указателей на массив нет.

Верхний `c` делает объект неизменяемым после инициализации. Константу нельзя изменить через `=`, `:=`, `++`, `--`; адрес константы имеет тип «указатель на константу».

```mfy
let x: int = 1;
let limit: c int = 10;
let px: p int = &x;          // указатель на int
let pl: pc int = &limit;     // указатель на константный int
let fixed: cp int = &x;      // константный указатель: сам fixed менять нельзя
$fixed = 2;                  // можно: объект x не константный
// fixed = px;               // ошибка проверки: fixed — константа
// $pl = 3;                  // ошибка проверки: $pl — неизменяемое lvalue
```

### 4.3 Массивы

Массив ранга k записывается с k размерами в квадратных скобках. Модификатор относится к элементам: `p int[3]` — массив из трёх указателей на `int`, `c int[]` — массив константных `int`.

| Запись | Где допускается | Смысл |
|---|---|---|
| `T[e1, ..., ek]` | `let` без инициализатора | массив ранга k с размерами `e1..ek`; размеры — выражения типа `int`, вычисляются при выполнении объявления |
| `T[]`, `T[,]`, `T[,,]`, … | параметры, возвращаемый тип, `let` с инициализатором | массив ранга 1, 2, 3, … без указания размеров |
| `T[N1, ..., Nk]`, `T[]` | поля структуры | размеры — только целые литералы; `[]` — пустой массив по умолчанию |

**Модель.** Массив ранга k — это массив, элементы которого — массивы ранга k−1. Размер не входит в тип: значение типа `int[]` может иметь любую длину, а строки двумерного массива — разную длину.

```mfy
let m: int[2, 3];        // 2 строки по 3 элемента, всё заполнено нулями
let row: int[] = m[0];   // строка — массив ранга 1
m[1] = [7, 8, 9, 10];    // строку можно заменить строкой другой длины
print m[1][3];           // 10
```

- **Индексация** с нуля: `a[i]`, `m[i][j]`. Каждая индексация снимает одно измерение: `int[,]` → `int[]` → `int`. Индекс вне `[0, length)` — ошибка выполнения. Отрицательный размер в объявлении — ошибка выполнения.
- **Длина**: `length(a)` — число элементов первого измерения.
- **Литерал**: `[1, 2, 3]`; для старших рангов — вложенный: `[[1, 2], [3, 4, 5]]`.
- **Копирование**: массив — значение. Инициализация, присваивание, передача аргументом и возврат из функции копируют его целиком (глубоко).
- **Ограничения**: массивы нельзя сравнивать (`==`), печатать (`print`) и брать на них указатель. Указатель на элемент брать можно: `&a[i]`.

### 4.4 Структуры

Структура определяется ключевым словом `type`:

```mfy
type Point {
    x, y: real;
}

type Segment {
    a, b: Point;
    label: str;
}

type Node {
    value: int;
    next: p Node;
}
```

- Определение — только на верхнем уровне. Имя — `IDENT` (не `MODWORD`), уникальное среди типов и функций. Тип виден во всей программе, в том числе выше определения.
- Поле: `имена : описатель_типа ;`. Имена полей уникальны внутри структуры и не конфликтуют с другими именами программы. Поле может иметь модификаторы; поле с `c` нельзя изменить после создания объекта.
- Методов и наследования нет.
- **Создание объекта**: `Point(1.0, 2.0)` — значения всех полей в порядке объявления, или `Point()` — все поля по умолчанию (§4.5). Результат — rvalue типа `Point`.
- **Доступ к полю**: `s.x`, через указатель — `ps->x`, что то же самое, что `($ps).x` (§6.4).
- **Копирование** глубокое, как у массивов.
- Структура не может содержать себя по значению, прямо или через другие структуры и массивы с размерами: это ошибка проверки. Через указатель (`p Node`) или массив без размеров (`Node[]`) — можно.
- Структуры нельзя сравнивать и печатать.

### 4.5 Значения по умолчанию

Используются для элементов массива, созданного по размерам, и для полей при `T()`.

| Тип | Значение по умолчанию |
|---|---|
| `int` | `0` |
| `real` | `0.0` |
| `bool` | `false` |
| `str` | `""` |
| любой указатель | `null` |
| структура | все поля по умолчанию |
| поле-массив `T[]` | пустой массив |
| поле-массив `T[N]` | N значений по умолчанию |

Скаляры, указатели и структуры без инициализатора объявлять нельзя (§7.1).

### 4.6 Совместимость типов и неявные преобразования

**Совпадение типов.** Базовые типы и структуры совпадают по имени. Указатели совпадают, если совпадают модификатор и базовый тип. Массивы совпадают, если совпадают тип элемента и ранг.

**Ожидаемый тип** есть в пяти контекстах: инициализатор в `let`, правая часть `=` и `:=`, аргумент функции (тип параметра), выражение в `return` (возвращаемый тип), аргумент создания структуры (тип поля).

Неявных преобразований ровно шесть:

| № | Из | В | Где действует |
|---|---|---|---|
| 1 | `int` | `real` | везде, где ожидается `real`: ожидаемый тип, операнды арифметики и сравнений, ветки тернарного оператора, элементы литерала массива |
| 2 | `bool` | `int`, `real` | только в операндах арифметических операторов `+ - * / %` и унарных `+ -` |
| 3 | `c T` | `T` | при копировании значения верхний `c` снимается: `let y: int = limit;` |
| 4 | `p X` | `pc X` | можно добавить `c` сразу после первой `p`: `p int` → `pc int`, `pp int` → `pcp int` |
| 5 | `null` | любой указатель | везде |
| 6 | литерал массива | `T[…]` ожидаемого типа | каждый элемент приводится к типу элемента; `[]` получает ожидаемый тип |

Всё остальное — только явно (§4.7) или запрещено. В частности, нет преобразований `real → int`, `int → bool`, между `str` и другими типами, между указателями на разные типы и между массивами с разными элементами: переменную типа `int[]` нельзя присвоить переменной типа `real[]`.

**Операции над разными типами** (арифметика):

| `a` | `b` | `a + b`, `a - b`, `a * b`, `a / b` | `a % b` |
|---|---|---|---|
| `int` | `int` | `int` | `int` |
| `int` | `real` | `real` | ошибка |
| `real` | `real` | `real` | ошибка |
| `bool` | `int` | `int` | `int` |
| `bool` | `bool` | `int` | `int` |
| `bool` | `real` | `real` | ошибка |
| `str` | `str` | `str` (только `+`, конкатенация) | ошибка |
| остальные сочетания | | ошибка проверки | ошибка проверки |

Таблица симметрична: `real + int` даёт то же, что `int + real`.

### 4.7 Явные преобразования

Записываются как `int(e)`, `real(e)`, `bool(e)`, `str(e)` (§6.3).

| Из \ В | `int` | `real` | `bool` | `str` |
|---|---|---|---|---|
| `int` | то же значение | ближайшее `double` | `e != 0` | десятичная запись |
| `real` | отбрасывание дробной части к нулю; NaN или вне диапазона `int` — ошибка выполнения | то же значение | `e != 0.0` | как при печати (§7.4) |
| `bool` | `0` / `1` | `0.0` / `1.0` | то же значение | `"true"` / `"false"` |
| `str` | разбор `[+-]?[0-9]+` по всей строке; иначе или вне диапазона — ошибка выполнения | разбор `[+-]?` и записи `INT_LIT` или `REAL_LIT` по всей строке; иначе — ошибка выполнения | только `"true"` или `"false"`; иначе — ошибка выполнения | то же значение |

Указатели, массивы и структуры преобразовывать нельзя (ошибка проверки). Пробелы вокруг числа в строке не допускаются: `int(" 5")` — ошибка выполнения.

## 5. Объекты, память и указатели

### 5.1 Объекты

Объект — ячейка памяти, хранящая значение определённого типа. Объектами являются каждая переменная (включая параметры), каждый элемент массива и каждое поле структуры. Литералы и промежуточные результаты объектами не являются, это rvalue.

### 5.2 Время жизни

- Локальная переменная живёт от выполнения её объявления до выхода из её области видимости (блока, `for`, вызова функции). Каждый вызов функции создаёт новые объекты для параметров и локальных переменных.
- Глобальная переменная живёт от выполнения её `let` до конца программы.
- Элемент массива и поле структуры живут, пока жив объект, который их содержит. Элемент живёт, пока его индекс меньше длины массива.

### 5.3 Копирование

Все значения копируются: при `let`, `=`, `:=`, передаче аргумента и возврате. Массивы и структуры копируются глубоко. Копия указателя хранит тот же адрес: оба указателя ссылаются на один объект.

```mfy
let a: int[] = [1, 2, 3];
let b: int[] = a;       // независимая копия
b[0] = 100;
print a[0];             // 1
```

Присваивание массива или структуры существующему объекту записывает значения поэлементно (по полям) в уже существующие подобъекты. Поэтому указатели на элементы и поля остаются действительными. Если новый массив короче, лишние элементы уничтожаются; если длиннее — создаются новые.

### 5.4 Указатели

- `&x` даёт адрес объекта `x`. Если `x: T`, то `&x: p T`; модификатор `x` сохраняется: при `x: c int` получается `pc int`, при `x: p int` — `pp int`.
- `$p` обозначает объект, на который указывает `p`; это lvalue.
- `null` ни на что не указывает.
- Арифметики указателей нет, указатели можно только сравнивать (`==`, `!=`).
- Разыменование `null` — ошибка выполнения. Разыменование указателя на объект, время жизни которого закончилось (висячий указатель), — тоже ошибка выполнения.
- Унарный `$` связывает слабее постфиксных операторов: `$p.x` означает `$(p.x)`. Поле через указатель: `p->x` (§6.4) или `($p).x`.

```mfy
def inc(target: p int) {
    $target = $target + 1;
}

let x: int = 41;
inc(&x);
print x;                // 42

def dangling(): p int {
    let local: int = 5;
    return &local;      // проверку проходит
}
let bad: p int = dangling();
print $bad;             // ошибка выполнения: висячий указатель
```

## 6. Выражения и операторы

### 6.1 Приоритеты и ассоциативность

Приоритеты соответствуют C++ ([cppreference](https://en.cppreference.com/w/cpp/language/operator_precedence)). Уровень 1 связывает сильнее всего.

| Уровень | Операторы | Арность | Ассоциативность | Результат |
|---|---|---|---|---|
| 1 | `f(…)` `T(…)` `int(…)` `a[i]` `s.f` `p->f` | постфиксные | слева направо | §6.3–6.4 |
| 2 | `++x` `--x` `+x` `-x` `not x` `$p` `&x` | унарные префиксные | справа налево | §6.5 |
| 3 | `*` `/` `%` | бинарные | слева направо | rvalue |
| 4 | `+` `-` | бинарные | слева направо | rvalue |
| 5 | `<` `<=` `>` `>=` | бинарные | неассоциативные | rvalue `bool` |
| 6 | `==` `!=` | бинарные | неассоциативные | rvalue `bool` |
| 7 | `and` | бинарный | слева направо | rvalue `bool` |
| 8 | `or` | бинарный | слева направо | rvalue `bool` |
| 9 | `c -> a \| b` | тернарный | справа налево | lvalue или rvalue |
| 10 | `:=` | бинарный | справа налево | rvalue |
| — | `=` | бинарный, **инструкция** | не цепляется | значения нет |

Отличия от C++:

- сравнения неассоциативны: `a < b < c` и `a == b == c` — синтаксические ошибки, пишите `a < b and b < c`;
- `:=` связывает слабее тернарного оператора: `c -> x | y := 1` означает `(c -> x | y) := 1`;
- постфиксных `x++` и `x--` нет;
- `$` вместо `*` для разыменования, `-> |` вместо `? :`, `and or not` вместо `&& || !`;
- `p->f` — как в C++, но тернарный `->` отличается от него пробелом перед лексемой (§2.2).

Примеры разбора:

| Выражение | Разбирается как |
|---|---|
| `-a * b` | `(-a) * b` |
| `a + b * c` | `a + (b * c)` |
| `a - b - c` | `(a - b) - c` |
| `not a and b` | `(not a) and b` |
| `a or b and c` | `a or (b and c)` |
| `a -> b \| c -> d \| e` | `a -> b \| (c -> d \| e)` |
| `$p.x` | `$(p.x)` |
| `p->x.y` | `(p->x).y` |
| `&p->x` | `&(p->x)` |
| `&a[i]` | `&(a[i])` |
| `-++x` | `-(++x)` |
| `x := y := 0` | `x := (y := 0)` |

### 6.2 Порядок вычисления

- Операнды бинарных операторов и аргументы вызова вычисляются слева направо. В `a[i]` сначала `a`, потом `i`.
- `and` и `or` вычисляются коротко (§6.9).
- В тернарном операторе сначала вычисляется условие, затем только выбранная ветка.
- В `=` и `:=` сначала вычисляется правая часть, затем левая, затем выполняется запись (как в C++17).
- В `let` с несколькими именами размеры и инициализатор вычисляются один раз; каждое имя получает свою копию значения.

### 6.3 Первичные выражения

#### Имя переменной `x`

- Вид: **lvalue**; изменяемое, если в типе `x` нет верхнего `c`.
- Имя функции или типа само по себе выражением не является, оно встречается только в вызове `f(…)` и создании `T(…)`.
- Ошибки проверки: имя не объявлено; имя объявлено ниже в той же или внешней области (кроме глобальных переменных в функциях, §8).

#### Литералы

- Вид: **rvalue**. Типы: `INT_LIT` — `int`, `REAL_LIT` — `real`, `STR_LIT` — `str`, `true`/`false` — `bool`, `null` — нулевой указатель, совместимый с любым указательным типом.

#### Скобки `(e)`

- Вид: **тот же, что у `e`** (lvalue остаётся lvalue). Тип тот же. Скобки только задают порядок разбора.

#### Литерал массива `[e1, …, en]`

- Вид: **rvalue**. n-арный, все элементы — **R**.
- Тип: если есть ожидаемый тип `T[…]`, каждый элемент неявно приводится к типу элемента, ранги должны совпадать. Без ожидаемого типа — `U[]`, где `U` — общий тип элементов: все типы одинаковы, или смесь `int` и `real` даёт `real`. Для старших рангов литералы вкладываются.
- Ошибки проверки: элементы несовместимых типов; пустой литерал `[]` без ожидаемого типа; элемент — void-выражение.

#### Вызов функции `f(a1, …, an)`

- Вид: **rvalue** возвращаемого типа; если функция `void` — **void-выражение**. n-арный, все аргументы — **R**.
- Число аргументов должно совпадать с числом параметров, каждый аргумент приводится к типу параметра как при инициализации. Аргументы копируются (§8).
- Ошибки проверки: функция не объявлена; `f` — не функция; неверное число или типы аргументов.

#### Создание структуры `T(a1, …, an)` и `T()`

- Вид: **rvalue** типа `T`. n-арный, все аргументы — **R**.
- Аргументов либо столько же, сколько полей (в порядке объявления, каждый приводится к типу поля), либо ни одного — тогда все поля по умолчанию.
- Ошибки проверки: неверное число или типы аргументов.

#### Явное преобразование `int(e)`, `real(e)`, `bool(e)`, `str(e)`

- Вид: **rvalue** указанного типа. Унарный, функциональная запись. Операнд — **R**.
- Правила — таблица §4.7. Ошибки проверки: преобразование указателя, массива, структуры или `void`. Ошибки выполнения: неудачный разбор строки, `real` вне диапазона `int`.

### 6.4 Постфиксные операторы

#### Индексация `a[i]`

- Вид: **lvalue**, если `a` — lvalue (изменяемое, если `a` изменяемое и в типе элемента нет верхнего `c`); иначе **rvalue**: `f()[0]`, `[1, 2][0]`.
- Бинарный, постфиксная запись. `a` — **R** типа массива, `i` — **R** типа `int` (`bool` не допускается).
- Тип результата — массив на одно измерение меньше или элемент: `int[,]` → `int[]` → `int`.
- Ошибки проверки: `a` не массив; `i` не `int`. Ошибка выполнения: `i < 0` или `i >= length(a)`.

#### Доступ к полю `s.f`

- Вид: **lvalue**, если `s` — lvalue (изменяемое, если `s` изменяемое и поле объявлено без `c`); иначе **rvalue**.
- Унарный, постфиксная запись (имя поля — не выражение). `s` — **R** типа структуры.
- Ошибки проверки: `s` не структура; в структуре нет поля `f`.

#### Доступ к полю через указатель `p->f`

- Вид: **lvalue** всегда; то же самое, что `($p).f`. Изменяемое, если структура, на которую указывает `p`, не константная и поле объявлено без `c`.
- Унарный, постфиксная запись (имя поля — не выражение). `p` — **R** типа «указатель на структуру»: `p T`, `pc T`, `cp T`, `cpc T`. `->` пишется вплотную к `p`, иначе это тернарный оператор (§2.2).
- Цепочки читаются слева направо: `list->next->value`.
- Ошибки проверки: `p` не указатель на структуру (в том числе `pp T` — пишите `($pp)->f`); в структуре нет поля `f`. Ошибки выполнения: `p` равен `null`; висячий указатель.

### 6.5 Унарные префиксные операторы

#### `++x`, `--x` — инкремент и декремент

- Вид: **lvalue** — сам объект `x` после изменения (как в C++). Поэтому допустимы `++++x` и `&(++x)`.
- Унарный, только префиксный. Операнд — **ML** типа `int` или `real`: переменная, элемент массива, поле, `$p`.
- Действие: `x` увеличивается (уменьшается) на 1. Переполнение `int` — ошибка выполнения.
- Постфиксных форм нет: `i++;` — синтаксическая ошибка.
- Ошибки проверки: операнд — rvalue (`++5`, `++(a + b)`); константа; тип `bool`, `str`, указатель и другие.

```mfy
++a[i];
--($p);
++count;
```

#### `+x`, `-x` — унарные плюс и минус

- Вид: **rvalue**. Унарный, префиксный. Операнд — **R** типа `int`, `real` или `bool` (`bool` → `int`).
- `-x` при `x`, равном минимальному `int`, — переполнение, ошибка выполнения.

#### `not x` — логическое «не»

- Вид: **rvalue** типа `bool`. Унарный, префиксный. Операнд — **R** типа `bool`.

#### `&x` — взятие адреса

- Вид: **rvalue** указательного типа: модификатор `x` с добавленной спереди `p` (`int` → `p int`, `c int` → `pc int`, `p int` → `pp int`).
- Унарный, префиксный. Операнд — **L** (в том числе неизменяемое).
- Ошибки проверки: операнд — rvalue (`&5`, `&f()`, `&(a + b)`); операнд — массив; получился указатель глубже двух уровней.

#### `$p` — разыменование

- Вид: **lvalue** — объект, на который указывает `p`. Изменяемое, если указуемый тип без `c`: при `p: p int` можно писать `$p = 1`, при `p: pc int` — нельзя.
- Унарный, префиксный. Операнд — **R** указательного типа.
- Ошибки проверки: операнд не указатель, в том числе литерал `null`. Ошибки выполнения: `p` равен `null`; висячий указатель.

### 6.6 Мультипликативные операторы

#### `a * b` — умножение

- Вид: **rvalue**. Бинарный, инфиксный. Оба операнда — **R**. Типы — таблица §4.6. Переполнение `int` — ошибка выполнения.

#### `a / b` — деление

- Вид: **rvalue**. Бинарный, инфиксный. Оба операнда — **R**.
- Если оба операнда целые (`int`/`bool`), деление целочисленное с отбрасыванием к нулю: `7 / 2 == 3`, `-7 / 2 == -3`. Если хотя бы один `real` — вещественное.
- Ошибки выполнения: деление на ноль (и `int`, и `real`); минимальный `int` / `-1` — переполнение.

#### `a % b` — остаток

- Вид: **rvalue** типа `int`. Бинарный, инфиксный. Оба операнда — **R** типа `int` или `bool`.
- Знак результата совпадает со знаком делимого: `-7 % 2 == -1`.
- Ошибка проверки: операнд `real`. Ошибка выполнения: `b == 0`.

### 6.7 Аддитивные операторы

#### `a + b` — сложение и конкатенация

- Вид: **rvalue**. Бинарный, инфиксный. Оба операнда — **R**.
- Числа — по таблице §4.6; `str + str` — конкатенация. `str + int` — ошибка проверки, пишите `"n = " + str(n)`.
- Переполнение `int` — ошибка выполнения.

#### `a - b` — вычитание

- Вид: **rvalue**. Бинарный, инфиксный. Оба операнда — **R** числовых типов по таблице §4.6.

### 6.8 Сравнения

#### `a < b`, `a <= b`, `a > b`, `a >= b`

- Вид: **rvalue** типа `bool`. Бинарные, инфиксные, **неассоциативные**. Оба операнда — **R**.
- Допустимые пары: два числа (`int`, `real`; при смеси `int` приводится к `real`) или две строки (лексикографически по байтам).
- `bool`, указатели, массивы и структуры не сравниваются: ошибка проверки.

#### `a == b`, `a != b`

- Вид: **rvalue** типа `bool`. Бинарные, инфиксные, **неассоциативные**. Оба операнда — **R**.
- Допустимые пары: два числа (с приведением `int` → `real`), два `bool`, две строки, два указателя на один базовый тип одной глубины (различия в `c` не учитываются), указатель и `null`.
- `bool == int` — ошибка проверки (приведение `bool` действует только в арифметике). Массивы и структуры не сравниваются.
- `real` сравниваются точно, без допуска.

### 6.9 Логические операторы

#### `a and b`, `a or b`

- Вид: **rvalue** типа `bool`. Бинарные, инфиксные, левоассоциативные. Оба операнда — **R** типа `bool`.
- Вычисляются коротко: в `a and b` операнд `b` вычисляется, только если `a` истинно; в `a or b` — только если `a` ложно.

### 6.10 Тернарный оператор `cond -> a | b`

- Вид: **lvalue**, если `a` и `b` — lvalue одного и того же типа (включая модификаторы); иначе **rvalue**.
- Тернарный. `cond` — **R** типа `bool`; `a`, `b` — **R** (или **L** для lvalue-результата).
- Тип результата: если типы веток совпадают — он же; `int` и `real` дают `real`; указатель и `null` — тип указателя; `p X` и `pc X` — `pc X`. Иначе ошибка проверки. Void-выражение в ветке — ошибка проверки.
- Вычисляется условие, затем **только выбранная** ветка.
- Перед `->` обязателен пробел (§2.2): `a>b -> a | b` корректно, а в `a>b-> a | b` лексема `->` читается как доступ к полю.
- Средний операнд — любое выражение (его ограничивают `->` и `|`), правый — выражение уровня 9 и ниже; оператор правоассоциативен.

```mfy
let m: int = a > b -> a | b;
let sign: int = x > 0 -> 1 | x < 0 -> -1 | 0;
(flag -> x | y) = 0;     // lvalue-результат: обнуляется x или y
```

### 6.11 Присваивание-выражение `a := b`

- Вид: **rvalue** — копия присвоенного значения; тип — тип `a` без верхнего `c`.
- Бинарный, инфиксный, правоассоциативный, самый низкий приоритет. Левый операнд — **ML**, правый — **R**; правый приводится к типу левого как при инициализации.
- Порядок: правая часть, левая часть, запись, результат.
- Отличие от `=`: `=` — инструкция, `:=` — выражение. Поэтому `a := b := 0;` допустимо, а `a = b = 0;` — нет.

```mfy
let line: str = "";
while (line := input()) != "end" {
    print line;
}
```

## 7. Инструкции

### 7.1 Объявление переменной `let`

```text
let имя1, имя2, … : [mod] тип [размеры] [= выражение] ;
```

- Вид: **инструкция** (объявление). Допускается на верхнем уровне (глобальная переменная), в блоке и в заголовке `for`.
- Инициализатор — **R**, приводится к объявленному типу как при инициализации (§4.6).

Правила:

1. Переменная скалярного типа, указателя или структуры обязана иметь инициализатор: `let n: int = 0;`, `let q: p int = null;`, `let pt: Point = Point();`.
2. Массив объявляется одним из двух способов: с размерами и без инициализатора (`let m: int[3, 4];`, элементы по умолчанию) или без размеров с инициализатором (`let a: int[] = [1, 2];`). Указать и то и другое или ни то ни другое — ошибка проверки. Ранг инициализатора должен совпадать с объявленным.
3. Имя становится видимым после конца объявления (после `;`). В `let x: int = x + 1;` справа используется внешняя `x`; если её нет — ошибка проверки.
4. Повторное объявление имени в той же области — ошибка проверки; затенение имени из внешней области разрешено (§9).
5. Имя не может совпадать с именем функции, типа или встроенной функции.
6. Тип `void` у переменной — ошибка проверки.
7. При нескольких именах инициализатор (и размеры) вычисляется один раз, каждое имя получает свою копию.

```mfy
let a, b, c: int = 0;
let ratio: real = 1;           // int → real
let name: c str = "MFY";
let grid: bool[n, n];          // n×n, всё false
let ptrs: p int[3];            // три указателя, все null
let pts: Point[10];            // десять точек по умолчанию
```

### 7.2 Присваивание `=`

```text
lvalue = выражение ;
```

- Вид: **инструкция**, не выражение: значения у неё нет, вложить её в выражение нельзя. Поэтому `a = b = 10;`, `if x = 1 { }`, `print x = 1;` — синтаксические ошибки.
- Бинарный, инфиксный. Левый операнд — **ML**, правый — **R**; правый приводится к типу левого.
- Порядок: правая часть, левая часть, запись.
- Массивы и структуры записываются в существующий объект поэлементно (§5.3).
- Может стоять в инициализации и шаге `for`.
- Ошибки проверки: слева не lvalue (`5 = x`, `f() = 1`, `a + b = c`); слева константа; несовместимые типы.

```mfy
x = 5;
a[i] = a[i - 1] + 1;
pt.x = 0.5;
node->value = 5;
$p = 10;
m[i][j] = 0;
```

### 7.3 Инструкция-выражение

```text
выражение ;
```

- Вид: **инструкция**. Допускается, только если выражение (без учёта внешних скобок) — вызов функции (результат отбрасывается), `++x`/`--x` или `:=`.
- Любое другое выражение — ошибка проверки «значение выражения не используется»: `a + 1;`, `x;`, `[1, 2];`.
- Void-выражение допустимо только здесь.

```mfy
hello();
++i;
assert(n > 0);
total := total * 2;
```

### 7.4 Вывод `print`

```text
print выражение ;
```

- Вид: **инструкция**. Операнд — **R** типа `int`, `real`, `bool` или `str`. Указатели, массивы, структуры и void-выражения печатать нельзя (ошибка проверки).
- Печатает значение и перевод строки в стандартный вывод.

| Тип | Формат |
|---|---|
| `int` | десятичная запись, `-` для отрицательных |
| `real` | кратчайшая запись, по которой значение восстанавливается однозначно. Из десятичной и экспоненциальной формы берётся более короткая (при равной длине — десятичная); экспонента пишется со знаком и минимум двумя цифрами. Если в записи нет `.`, `e`, `inf`, `nan`, дописывается `.0`: `2.0`, `0.1`, `1e+21`, `-0.5` |
| `bool` | `true` или `false` |
| `str` | содержимое строки как есть |

### 7.5 Блок

```text
{ инструкция … }
```

- Вид: **составная инструкция**. Создаёт новую область видимости; объекты, объявленные в блоке, уничтожаются при выходе из него. Блок может стоять отдельной инструкцией.

### 7.6 Ветвление `if`

```text
if условие { … }
if условие { … } else { … }
if условие { … } else if условие { … } else { … }
```

- Вид: **составная инструкция**. Условие — **R** типа `bool`: целое как условие не подходит, пишите `if n != 0`.
- Скобки вокруг условия необязательны, это просто скобки выражения: `if (x > 0) { }` и `if x > 0 { }` равнозначны.
- Тело — всегда блок `{ }`. Так однозначно видно, где кончается условие без скобок.
- После `if` обязателен пробел (§2.2).

### 7.7 Цикл `while`

```text
while условие { … }
```

- Вид: **составная инструкция**. Условие — **R** типа `bool`, проверяется перед каждой итерацией. Скобки необязательны, тело — блок, после `while` обязателен пробел.

### 7.8 Цикл `for`

```text
for (инициализация; условие; шаг) { … }
for инициализация; условие; шаг { … }
```

- Вид: **составная инструкция**.
- Инициализация: пусто, объявление `let`, присваивание или инструкция-выражение. Условие: пусто (означает `true`) или **R** типа `bool`. Шаг: пусто, присваивание или инструкция-выражение.
- `for` создаёт свою область видимости: переменная из инициализации видна в условии, шаге и теле, но не после цикла. Тело — вложенная область.
- Порядок: инициализация один раз; перед каждой итерацией условие; тело; шаг. `continue` переходит к шагу, `break` выходит из цикла.
- Если сразу после `for` стоит `(`, заголовок разбирается в скобках. Поэтому в форме без скобок инициализация не может начинаться с `(`.
- Тело — блок, после `for` обязателен пробел.

```mfy
for (let i: int = 0; i < 10; ++i) { print i; }
for let i: int = 9; i >= 0; --i { print i; }
for (;;) { break; }
```

### 7.9 `break` и `continue`

- Вид: **простая инструкция**, операндов нет. Действуют на ближайший объемлющий цикл.
- Допустимы только внутри тела цикла (на любой глубине блоков, но не через границу функции). Вне цикла — ошибка проверки.

### 7.10 `return`

```text
return ;
return выражение ;
```

- Вид: **простая инструкция**. Выражение — **R**, приводится к возвращаемому типу.
- Допустима только внутри функции; на верхнем уровне программы — ошибка проверки.
- В `void`-функции разрешён только `return;`; в остальных обязателен `return выражение;`.
- Функция с результатом не должна доходить до конца тела без `return`. Проверка консервативная. Инструкция «всегда завершается `return`», если это:
  - `return`;
  - блок, в котором хотя бы одна инструкция всегда завершается `return`;
  - `if … else …`, обе ветки которого всегда завершаются `return`.

  `if` без `else`, `while` и `for` (даже `while true`) так не считаются. После такого цикла нужен явный `return`.

## 8. Функции

```text
def имя(п1: [mod] тип, п2: [mod] тип, …): [mod] тип { тело }
def имя(п1: [mod] тип, …) { тело }                   // ничего не возвращает
```

- Вид: **определение**. Только на верхнем уровне; функция внутри функции или блока — синтаксическая ошибка.
- Имя — `IDENT` или `MODWORD`, уникальное среди функций, типов и встроенных функций; глобальная переменная не может называться так же. Перегрузки нет.
- **Параметры**: `имя: описатель_типа`. Массивы — без размеров: `a: int[]`, `m: real[,]`. Повторяющиеся имена параметров — ошибка проверки. Параметры и верхний блок тела — одна область: `let` с именем параметра в теле — повторное объявление. Параметр с `c` нельзя менять.
- **Возвращаемый тип**: если не указан — `void` (можно написать `: void` явно). Массивы — без размеров. Верхний `c` у возвращаемого типа ничего не меняет.
- **Передача по значению**: аргументы копируются (массивы и структуры — глубоко). Чтобы изменить объект вызывающей стороны, передавайте указатель.
- **Вызов**: каждый вызов получает собственное окружение — новые объекты параметров и локальных переменных. Рекурсия и взаимная рекурсия разрешены. Функцию можно вызывать до её определения в тексте.
- **Что видно в теле**: параметры и локальные переменные, все глобальные переменные (где бы в файле они ни были объявлены), все функции и типы. Локальные переменные вызывающей функции не видны: области видимости статические.
- Чтение глобальной переменной, чей `let` ещё не выполнился, — ошибка выполнения.
- **Глубина рекурсии** ограничена; превышение — ошибка выполнения «переполнение стека вызовов». Предел задаёт интерпретатор, но не меньше 1 000 вложенных вызовов.
- Функции нельзя присваивать, передавать и возвращать как значения.

```mfy
def hello() {
    print "Hello";
}

def swap(a: p int, b: p int) {
    let t: int = $a;
    $a = $b;
    $b = t;
}

def isEven(n: int): bool {
    if n == 0 { return true; }
    return isOdd(n - 1);       // isOdd определена ниже — это допустимо
}

def isOdd(n: int): bool {
    if n == 0 { return false; }
    return isEven(n - 1);
}
```

## 9. Области видимости

Виды областей:

| Область | Что создаёт | Что в ней объявлено |
|---|---|---|
| глобальная | программа | `let` верхнего уровня, все функции и типы |
| функции | вызов функции | параметры и `let` верхнего блока тела |
| блока | `{ }` | `let` внутри блока |
| `for` | заголовок `for` | `let` из инициализации |

- Имя ищется от внутренней области к внешним. Внешняя для области функции — глобальная, а не область вызывающей функции.
- Повторное объявление имени в той же области — ошибка проверки. Затенение имени переменной из внешней области разрешено.
- Имена функций и типов не затеняются: объявить переменную или параметр с таким именем нельзя нигде.
- Имена полей живут в своей структуре и не пересекаются с остальными.
- Переменная видна после конца своего объявления (§7.1). Исключение: в теле функции видны все глобальные переменные.

```mfy
let x: int = 1;
{
    let x: str = "inner";    // затенение — допустимо
    print x;                 // inner
}
print x;                     // 1
let x: int = 2;              // ошибка проверки: повторное объявление x
```

## 10. Программа и порядок выполнения

- Программа — один файл: последовательность элементов верхнего уровня, то есть определений (`def`, `type`) и инструкций вперемешку. Функции `main` нет.
- Программа, в которой есть хотя бы одна лексическая, синтаксическая или семантическая ошибка, не выполняется вовсе.
- Выполняются инструкции верхнего уровня по порядку. Определения не выполняются.
- Глобальные переменные — это `let` прямо на верхнем уровне; `let` внутри блока верхнего уровня — локальные.
- Программа завершается после последней инструкции или на первой ошибке выполнения.

## 11. Встроенные функции

| Сигнатура | Действие | Ошибки |
|---|---|---|
| `input(): str` | читает строку из стандартного ввода без завершающего `\n` (или `\r\n`) | выполнения: конец ввода |
| `length(a): int` | число элементов первого измерения массива `a` любого типа и ранга | проверки: `a` не массив |
| `assert(cond: bool)` | ничего не делает, если `cond` истинно | выполнения: `cond` ложно — «assertion failed» |
| `assert(cond: bool, message: str)` | то же, с текстом сообщения | выполнения: «assertion failed: message» |

Преобразования `int(e)`, `real(e)`, `bool(e)`, `str(e)` записываются как вызовы, но являются операторами (§4.7, §6.3).

Имена `input`, `length`, `assert` зарезервированы: объявить с ними переменную, функцию или тип нельзя.

## 12. Ошибки

### 12.1 Виды ошибок

| Вид | Когда обнаруживается | Что происходит |
|---|---|---|
| лексическая | до запуска | программа не выполняется |
| синтаксическая | до запуска | программа не выполняется |
| семантическая (ошибка проверки) | до запуска | программа не выполняется |
| ошибка выполнения | во время работы | программа останавливается на этой ошибке |

Каждая ошибка сообщается с позицией в исходном тексте. Лексические ошибки перечислены в §2.8, остальные — ниже.

### 12.2 Каталог ошибок

**Синтаксические**

| Ситуация | Пример |
|---|---|
| Нарушение грамматики | `let x int = 1;` — ожидалось `:` |
| Цепочка присваиваний | `a = b = 1;` |
| Ключевое слово вместо имени | `let while: int = 1;` |
| Постфиксный инкремент | `i++;` |
| Цепочка сравнений | `if a < b < c { }` |
| Тернарный `->` без пробела перед ним | `x>0-> 1 \| 2` — `->` вплотную читается как доступ к полю |
| Тело без фигурных скобок | `if x > 0 print x;` |
| `def` или `type` внутри блока | `{ def f() { } }` |
| Модификатор из двух слов | `let q: p p int = null;` |
| Имя структуры из букв `p`, `c` | `type pc { x: int; }` |

**Проверки (semantic)**

| Ситуация | Пример |
|---|---|
| Необъявленная переменная, функция или тип | `print y;`, `foo();`, `let a: Foo = Foo();` |
| Повторное объявление в той же области | `let x: int = 1; let x: int = 2;` |
| Имя занято функцией, типом или встроенной функцией | `let length: int = 0;` |
| Несовместимые типы в инициализации, присваивании, аргументе, `return`, операции | `let n: int = "5";`, `"a" - 1` |
| Условие не `bool` | `if n { }` при `n: int` |
| Присваивание не lvalue | `5 = x;`, `f() = 1;` |
| Изменение константы | `limit = 3;`, `++limit;` при `limit: c int` |
| `++`/`--` от rvalue или нечислового типа | `++5;`, `++flag;` |
| `&` от rvalue или массива; указатель глубже двух уровней | `&(a + 1)`, `&arr`, `&pp` при `pp: pp int` |
| `$` от не указателя | `$x` при `x: int` |
| Неверное число аргументов; вызов не функции | `fact(1, 2)`, `x(1)` |
| `return` вне функции; значение в `void`-функции; нет значения или не все пути возвращают | `return 1;` на верхнем уровне |
| `break`/`continue` вне цикла | `break;` на верхнем уровне |
| Значение выражения не используется | `a + 1;` |
| Void-выражение как значение; переменная или параметр типа `void` | `let v: int = hello();` |
| Недопустимый модификатор | `ppp int`, `cc int` |
| Размеры массива в параметре или возвращаемом типе; и размеры, и инициализатор; ни того ни другого; размер не `int` | `def f(a: int[3])`, `let a: int[2] = [1, 2];`, `let a: int[];` |
| Скаляр, указатель или структура без инициализатора | `let n: int;` |
| Индексация не массива; индекс не `int` | `x[0]` при `x: int`, `a[true]` |
| Нет такого поля; поле не у структуры | `pt.z`, `n.x` при `n: int` |
| `->` не от указателя на структуру | `pt->x` при `pt: Point` |
| Неверные аргументы создания структуры | `Point(1.0)` |
| Структура содержит себя по значению | `type A { a: A; }` |
| Печать недопустимого типа | `print arr;`, `print p;` |
| Литерал массива: разнородные элементы; `[]` без ожидаемого типа | `[1, "a"]` |
| Недопустимое преобразование | `int(ptr)`, `str(arr)` |
| Недопустимое сравнение | `true < false`, `arr == arr`, `flag == 1` |

**Выполнения (runtime)**

| Ситуация | Пример |
|---|---|
| Деление или остаток на ноль | `1 / 0`, `1.0 / 0.0`, `5 % 0` |
| Переполнение `int` | `9223372036854775807 + 1` |
| Индекс вне границ массива | `a[3]` при `length(a) == 3`, `a[-1]` |
| Отрицательный размер массива | `let a: int[n];` при `n == -1` |
| Разыменование `null` | `$q` при `q == null` |
| Висячий указатель | указатель на локальную переменную завершившейся функции |
| Неудачное преобразование | `int("abc")`, `bool("yes")`, `int(1e300)` |
| Ложный `assert` | `assert(1 > 2)` |
| `input()` в конце ввода | |
| Превышена глубина рекурсии | бесконечная рекурсия |
| Чтение глобальной переменной до её `let` | функция читает глобальную, объявленную ниже места вызова |

## 13. Грамматика

```ebnf
(* ---------- программа ---------- *)
program      = { top_item } EOF ;
top_item     = func_def | type_def | statement ;

(* ---------- определения ---------- *)
func_def     = "def" name "(" [ param { "," param } ] ")" [ ":" type_spec ] block ;
param        = name ":" type_spec ;
type_def     = "type" IDENT "{" { field_decl } "}" ;
field_decl   = name_list ":" type_spec ";" ;

(* ---------- типы ---------- *)
type_spec    = [ MODWORD ] base_type [ dims ] ;
base_type    = "int" | "real" | "bool" | "str" | "void" | IDENT ;
dims         = "[" [ expr { "," expr } | "," { "," } ] "]" ;

(* ---------- инструкции ---------- *)
statement    = block
             | let_decl ";"
             | if_stmt
             | while_stmt
             | for_stmt
             | "break" ";"
             | "continue" ";"
             | "return" [ expr ] ";"
             | "print" expr ";"
             | simple_stmt ";" ;
block        = "{" { statement } "}" ;
let_decl     = "let" name_list ":" type_spec [ "=" expr ] ;
name_list    = name { "," name } ;
simple_stmt  = expr [ "=" expr ] ;          (* присваивание или инструкция-выражение *)
if_stmt      = "if" expr block [ "else" ( if_stmt | block ) ] ;
while_stmt   = "while" expr block ;
for_stmt     = "for" ( "(" for_header ")" | for_header ) block ;
for_header   = [ for_init ] ";" [ expr ] ";" [ simple_stmt ] ;
for_init     = let_decl | simple_stmt ;

(* ---------- выражения ---------- *)
expr         = ternary [ ":=" expr ] ;
ternary      = or_expr [ COND_ARROW expr "|" ternary ] ;
or_expr      = and_expr { "or" and_expr } ;
and_expr     = eq_expr { "and" eq_expr } ;
eq_expr      = rel_expr [ ( "==" | "!=" ) rel_expr ] ;
rel_expr     = add_expr [ ( "<" | "<=" | ">" | ">=" ) add_expr ] ;
add_expr     = mul_expr { ( "+" | "-" ) mul_expr } ;
mul_expr     = unary { ( "*" | "/" | "%" ) unary } ;
unary        = ( "++" | "--" | "+" | "-" | "not" | "$" | "&" ) unary
             | postfix ;
postfix      = primary { "[" expr "]" | "." name | PTR_ARROW name } ;
primary      = name [ args ]                (* переменная, вызов, создание структуры *)
             | cast_type "(" expr ")"
             | "(" expr ")"
             | "[" [ expr { "," expr } ] "]"
             | INT_LIT | REAL_LIT | STR_LIT | "true" | "false" | "null" ;
args         = "(" [ expr { "," expr } ] ")" ;
cast_type    = "int" | "real" | "bool" | "str" ;
name         = IDENT | MODWORD ;
```

- `COND_ARROW` и `PTR_ARROW` — две лексемы `->`, которые различаются пробелом перед ними (§2.2).
- Если сразу после `for` стоит `(`, выбирается альтернатива с заголовком в скобках (§7.8).
- Грамматика шире языка: что слева от `=` стоит изменяемое lvalue, допустимость модификатора, места для размеров массива и прочие ограничения задаются правилами §4–§8.

## 14. Расширения (необязательная часть)

Берёмся за них только после того, как работает весь базовый язык. Синтаксис зафиксирован заранее, чтобы расширения не ломали базовый язык.

### 14.1 Реактивные переменные

```mfy
let price: int = 10;
let count: int = 2;
reactive total: int = price * count;   // объявление
count = 3;
print total;                           // 30
reactive total = price * count * 2;    // перепривязка к новому выражению
```

- `reactive имя: тип = выражение;` — объявление (инструкция). Значение реактивной переменной при каждом чтении равно значению выражения на текущих значениях зависимостей. Реализация может пересчитывать при изменении зависимостей или при чтении.
- `reactive имя = выражение;` (без типа) — перепривязка уже объявленной реактивной переменной.
- Имя реактивной переменной — rvalue: его нельзя присваивать, инкрементировать и брать от него адрес.
- В выражении допустимы литералы, переменные (в том числе реактивные), операторы и преобразования типов. Запрещены вызовы функций, `:=`, `++`, `--`, `$`, `&`.
- Проверка строит граф зависимостей по всем объявлениям и перепривязкам (без учёта порядка выполнения) и сообщает о циклах как об ошибке проверки.

### 14.2 Поиск неинициализированных переменных

- Разрешается объявлять локальные скаляры, указатели и структуры без инициализатора: `let n: int;`.
- Проверка находит чтения, перед которыми хотя бы на одном пути нет присваивания (анализ «определённого присваивания»), и сообщает о них как об ошибке проверки.
- Правила: после `if`/`else` переменная присвоена, если присвоена в обеих ветках; после `if` без `else` — если была присвоена до него. Тело цикла может не выполниться ни разу, поэтому присваивания в теле `while`/`for` не учитываются после цикла; тело анализируется от состояния перед циклом. `break`, `continue`, `return` обрывают путь. Взятие адреса `&x` от возможно неинициализированной переменной считается чтением.
- Глобальные переменные по-прежнему требуют инициализатор.

### 14.3 Вложенные массивы

Уже входят в базовый язык: многомерные массивы `T[N1, N2]` и индексация `m[i][j]` (§4.3).

### 14.4 Подключение файлов

```mfy
include "lib/math.mfy";
```

- Только на верхнем уровне. Путь — относительно каталога подключающего файла. Содержимое вставляется как элементы верхнего уровня.
- Каждый файл подключается не более одного раза; повторное подключение молча пропускается. Циклическое подключение — ошибка с цепочкой имён файлов. Сообщение об ошибке указывает, в каком файле она произошла.

### 14.5 Параметры по умолчанию

```mfy
def greet(name: str, times: int = 1) { … }
greet("MFY");
```

- Значения по умолчанию — только у последних параметров. Выражение по умолчанию содержит только литералы и операторы и вычисляется при каждом вызове.

### 14.6 Константы

Уже входят в базовый язык: модификатор `c` (§4.2).

### 14.7 Перечисления

```mfy
enum Color { Red, Green, Blue }
let c: Color = Color.Red;
```

- Только на верхнем уровне. Значения — `Тип.Имя` (rvalue). Допустимы `==`, `!=`, `int(e)` (номер с нуля), `str(e)` (имя), `print`.

### 14.8 Неявные преобразования `int → real`

Уже входят в базовый язык (§4.6).

### 14.9 `random`

- `random(lo: int, hi: int): int` — целое из `[lo, hi]`; `lo > hi` — ошибка выполнения.
- Последовательность воспроизводима: генератор — 64-битный вихрь Мерсенна (MT19937-64), начальное значение задаёт интерпретатор (по умолчанию 0). Очередное число `x` генератора даёт результат `lo + x mod (hi − lo + 1)`.

## 15. Примеры программ

### 15.1 Матрица

```mfy
def transpose(m: int[,]): int[,] {
    let rows: int = length(m);
    let cols: int = length(m[0]);
    let t: int[cols, rows];
    for (let i: int = 0; i < rows; ++i) {
        for (let j: int = 0; j < cols; ++j) {
            t[j][i] = m[i][j];
        }
    }
    return t;
}

let m: int[,] = [[1, 2, 3], [4, 5, 6]];
let t: int[,] = transpose(m);
print t[2][1];      // 6
```

### 15.2 Структуры и указатели

```mfy
type Point {
    x, y: real;
}

def shift(pt: p Point, dx: real, dy: real) {
    pt->x = pt->x + dx;
    pt->y = pt->y + dy;
}

let a: Point = Point(1.0, 2.0);
shift(&a, 0.5, -1);     // -1: int → real
print a.x;              // 1.5
print a.y;              // 1.0
```

### 15.3 Ввод, `:=` и тернарный оператор

```mfy
let total: int = 0;
let line: str = "";
while (line := input()) != "end" {
    total = total + int(line);
}
print "sum = " + str(total);
print total % 2 == 0 -> "even" | "odd";
```

### 15.4 Константы и указатель на указатель

```mfy
let x: int = 1;
let px: p int = &x;
let ppx: pp int = &px;
$$ppx = 5;              // $($ppx) — это x
print x;                // 5

let size: c int = 3;
let view: pc int = &size;
print $view + 1;        // 4
```

### 15.5 Связный список

```mfy
type Node {
    value: int;
    next: p Node;
}

let third: Node = Node(3, null);
let second: Node = Node(2, &third);
let first: Node = Node(1, &second);

let sum: int = 0;
let cur: p Node = &first;
while cur != null {
    sum = sum + cur->value;
    cur = cur->next;
}
print sum;                        // 6
print first.next->next->value;    // 3
```
