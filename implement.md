## 1. Конвейер

```text
исходный текст → сканер → лексемы → парсер LL(1) → AST → проверка → исполнение
                 tokens            ast, ast-dot          check       run, repl
```

- Интерпретатор пишется на C++. Каждый этап — отдельный модуль со своим входом и выходом.
- Проверка и исполнение — два отдельных прохода по AST. Исполнение начинается, только если сканер, парсер и проверка прошли без ошибок.

| Итерация задания | Этапы | Команды |
|---|---|---|
| 1. Сканер | §2 | `tokens` |
| 2. Парсер и AST | §3, §4 | `ast`, `ast-dot` |
| 3. Проверка и исполнение | §5, §6 | `check`, `run`, `repl` |

## 2. Сканер

### 2.1 Автомат

- Сканер — конечный автомат с собственным кодом переходов, без библиотек регулярных выражений. Правила лексики — README §2.
- **Самая длинная лексема.** Автомат идёт по символам, пока есть переход, и запоминает последнее принимающее состояние и позицию, где оно было. В тупике сканер откатывается к этой позиции и выдаёт лексему. Если принимающего состояния не было, это лексическая ошибка.
- **Приоритет при равной длине**: ключевое слово, затем `MODWORD`, затем `IDENT`. Удобно распознавать слово целиком как идентификатор, а затем проверять таблицу ключевых слов и шаблон `[pc]+`.
- Пробелы и комментарии пропускаются, но сканер запоминает, были ли они перед очередной лексемой (поле `spaceBefore`).
- Два правила README §2.2 зависят от пробелов, их проверяет сканер:
  - после лексем `IF`, `WHILE`, `FOR` следующий символ должен быть пробельным, иначе лексическая ошибка;
  - лексема `->` получает вид `COND_ARROW` (тернарный оператор), если `spaceBefore` истинно, и `PTR_ARROW` (поле через указатель), если она стоит вплотную к предыдущей лексеме. Парсер получает две разные лексемы, поэтому таблица LL(1) не получает конфликта.

### 2.2 Лексема и позиции

```cpp
struct Position {
    int line;      // с 1
    int column;    // с 1
};

struct Token {
    TokenKind kind;
    std::string lexeme;    // текст как в исходнике
    Position start;        // первый символ
    Position end;          // последний символ, включительно
    bool spaceBefore;      // перед лексемой были пробелы, переводы строк или комментарии
};
```

- Столбец считается в символах Unicode: байты-продолжения UTF-8 (вида `10xxxxxx`) столбец не увеличивают. Табуляция занимает один столбец.
- `\r\n` — один перевод строки.
- `EOF` стоит в позиции сразу после последнего символа файла.

### 2.3 Виды лексем

| Лексема | Вид |
|---|---|
| ключевые слова `let`, `def`, `while`, `int`, … | слово в верхнем регистре: `LET`, `DEF`, `WHILE`, `INT`, … |
| идентификатор | `IDENT` |
| слово из букв `p` и `c` | `MODWORD` |
| целый, вещественный, строковый литерал | `INT_LIT`, `REAL_LIT`, `STR_LIT` |
| `+` `-` `*` `/` `%` | `PLUS` `MINUS` `STAR` `SLASH` `PERCENT` |
| `++` `--` | `INC` `DEC` |
| `=` `:=` | `ASSIGN` `WALRUS` |
| `==` `!=` | `EQ` `NE` |
| `<` `<=` `>` `>=` | `LT` `LE` `GT` `GE` |
| `->` с пробелом перед ним, `\|` | `COND_ARROW` `PIPE` |
| `->` вплотную к предыдущей лексеме | `PTR_ARROW` |
| `$` `&` `.` | `DOLLAR` `AMP` `DOT` |
| `(` `)` `[` `]` `{` `}` | `LPAREN` `RPAREN` `LBRACKET` `RBRACKET` `LBRACE` `RBRACE` |
| `,` `;` `:` | `COMMA` `SEMI` `COLON` |
| конец файла | `EOF` |

## 3. Парсер

### 3.1 Таблица LL(1)

- Грамматика — README §13. Перед построением таблицы EBNF переводится в BNF:
  - `{ x }` → новый нетерминал `T = x T | ε`;
  - `[ x ]` → новый нетерминал `O = x | ε`;
  - группа `( a | b )` → новый нетерминал с альтернативами `a` и `b`.
- Вычисляются обнуляемость, FIRST и FOLLOW, затем строится таблица `[нетерминал, лексема] → правило`. Если в ячейку попадают два правила, это конфликт: программа построения таблицы печатает его с объяснением (какие множества FIRST или FOLLOW пересеклись).
- Левой рекурсии в грамматике нет. Левоассоциативные операторы заданы повторениями `{ op x }`; при построении AST хвост сворачивается слева направо: `a - b - c` → `Binary(-, Binary(-, a, b), c)`.
- Неассоциативные сравнения заданы через `[ … ]`, поэтому `a < b < c` даёт синтаксическую ошибку. Правоассоциативные тернарный оператор и `:=` заданы правой рекурсией.

### 3.2 Единственный конфликт

В `for_stmt` лексема `(` входит и в FIRST альтернативы `"(" for_header ")"`, и в FIRST `for_header` (выражение в инициализации может начинаться со скобки). Конфликт разрешается в пользу заголовка в скобках: в ячейку `[for_stmt-хвост, "("]` записывается первая альтернатива. Следствие для языка описано в README §7.8.

«Висячего `else`» нет: тела `if` всегда блоки.

### 3.3 Синтаксические ошибки

- Разбор останавливается на первой ошибке, восстановления нет.
- Если на вершине стека терминал, не совпадающий с текущей лексемой, сообщение — «ожидалось 'X'», где X — этот терминал. Если нетерминал с пустой ячейкой, ожидаемые лексемы — все терминалы с непустыми ячейками в его строке таблицы.
- Пример: в `a = b = 1;` после `a = b` лексема `=` входит в FOLLOW(`expr`), поэтому применяются ε-правила, пока на вершине стека не окажется `;`. Сообщение: `ожидалось ';', получено '='`.

### 3.4 Что остаётся проверке

Грамматика намеренно шире языка. После разбора проверка (§5) отсеивает:

- не-lvalue и неизменяемое lvalue слева от `=` и `:=`;
- недопустимые слова-модификаторы (README §4.2);
- размеры массива там, где они запрещены;
- выражения, которые не могут быть инструкцией-выражением;
- `void` вне возвращаемого типа функции.

## 4. AST

### 4.1 Узлы

У каждого узла есть диапазон в исходном тексте.

| Узел | Поля |
|---|---|
| `Program` | элементы верхнего уровня |
| `FuncDef` | имя, параметры, возвращаемый тип (может отсутствовать), тело |
| `Param` | имя, тип |
| `TypeDef` | имя, поля |
| `Field` | имя, тип |
| `TypeSpec` | модификатор, базовый тип, ранг, выражения размеров |
| `Block` | инструкции |
| `Let` | имена, тип, инициализатор (может отсутствовать) |
| `Assign` | цель, значение |
| `ExprStmt` | выражение |
| `Print` | выражение |
| `If` | условие, ветка «то», ветка «иначе» (может отсутствовать) |
| `While` | условие, тело |
| `For` | инициализация, условие, шаг (каждое может отсутствовать), тело |
| `Break`, `Continue` | — |
| `Return` | значение (может отсутствовать) |
| `IntLit`, `RealLit`, `StrLit`, `BoolLit`, `NullLit` | значение |
| `ArrayLit` | элементы |
| `Name` | имя |
| `Call` | имя, аргументы (вызов функции или создание структуры — различается на проверке) |
| `Cast` | целевой тип, операнд |
| `Index` | массив, индекс |
| `Member` | объект, имя поля (`s.f`) |
| `PtrMember` | указатель, имя поля (`p->f`) |
| `Unary` | оператор (`++ -- + - not $ &`), операнд |
| `Binary` | оператор (`* / % + - < <= > >= == !=`), левый, правый |
| `Logical` | оператор (`and`, `or`), левый, правый |
| `Ternary` | условие, ветка «то», ветка «иначе» |
| `AssignExpr` | цель, значение (`:=`) |

### 4.2 Формат `ast`

Один узел на строку, отступ — два пробела на уровень: `Вид атрибуты @начало-конец`. Для `let x: int = 1 + 2;`:

```text
Program @1:1-1:19
  Let names=[x] @1:1-1:19
    TypeSpec base=int @1:8-1:10
    Binary op=+ @1:14-1:18
      IntLit 1 @1:14-1:14
      IntLit 2 @1:18-1:18
```

### 4.3 Формат `ast-dot`

Узлы нумеруются в прямом порядке обхода (`n0` — корень), подпись — как в `ast`, но без позиций. Рёбра идут от родителя к детям в порядке детей. Вывод сверяется с эталонным на небольших программах.

```text
digraph AST {
  node [shape=box];
  n0 [label="Program"];
  n1 [label="Let names=[x]"];
  n2 [label="TypeSpec base=int"];
  n3 [label="Binary op=+"];
  n4 [label="IntLit 1"];
  n5 [label="IntLit 2"];
  n0 -> n1;
  n1 -> n2;
  n1 -> n3;
  n3 -> n4;
  n3 -> n5;
}
```

## 5. Проверка

- **Проход 1** собирает определения верхнего уровня: функции, структуры и глобальные переменные (имена и типы). Поэтому функцию можно вызвать до её определения, а в теле функции видны все глобальные переменные. Здесь же ищутся повторные имена и структуры, содержащие себя по значению (поиск цикла в графе «структура → типы её полей по значению»).
- **Проход 2** обходит AST со стеком областей видимости: разрешает имена, вычисляет тип и категорию каждого выражения (rvalue, lvalue, изменяемость), отмечает неявные преобразования, следит за контекстом (внутри цикла, внутри функции), проверяет, что функция с результатом всегда завершается `return`.
- Узлы `Call` помечаются: вызов функции, вызов встроенной функции или создание структуры.
- Ошибки не останавливают проверку: собираются все и выводятся по порядку позиций. Выражение с ошибкой получает особый «ошибочный» тип, который совместим со всем, чтобы одна ошибка не порождала цепочку следующих.

## 6. Исполнение

Исполнитель обходит проверенный AST.

### 6.1 Представление значений

| Тип MFY | Представление в C++ |
|---|---|
| `int` | `long long` |
| `real` | `double` |
| `bool` | `bool` |
| `str` | `std::string` |
| указатель | `std::weak_ptr<Cell>`; пустой — `null` |
| массив | `std::vector<std::shared_ptr<Cell>>`; массив ранга k хранит в ячейках массивы ранга k−1, как `vector<vector<T>>` |
| структура | ячейки полей в порядке объявления |

Значение — `std::variant` из этих вариантов. Объявление `let m: int[2, 3];` создаёт то же, что `vector<vector<long long>> m(2, vector<long long>(3))`.

### 6.2 Объекты и указатели

- Объект (переменная, элемент массива, поле) — ячейка `Cell` со значением, которой владеет `std::shared_ptr<Cell>`.
- Указатель хранит `std::weak_ptr<Cell>`. Разыменование: пустой указатель — ошибка «разыменование null»; `expired()` — ошибка «висячий указатель».
- Копирование значения (`let`, `=`, `:=`, аргумент, `return`) глубокое: для массивов и структур создаются новые ячейки.
- Присваивание массива или структуры существующему объекту пишет значения в уже существующие ячейки, поэтому указатели на элементы и поля остаются действительными. Лишние ячейки удаляются, недостающие создаются.

### 6.3 Окружения и вызовы

- Каждый вызов функции создаёт новое окружение — стек областей видимости; внешнее для него — глобальное окружение.
- Счётчик глубины вызовов: предел — 10 000 вложенных вызовов, превышение — ошибка выполнения «переполнение стека вызовов».
- Исполнитель рекурсивен, поэтому 10 000 вызовов MFY могут не поместиться в стандартный стек процесса. Исполнение запускается в отдельном потоке с увеличенным стеком (например, 256 МБ через `pthread_attr_setstacksize`).
- У глобальной переменной есть признак «ещё не инициализирована» до выполнения её `let`; чтение такой переменной — ошибка выполнения.
- `and`, `or` и тернарный оператор вычисляют второй (выбранный) операнд только при необходимости.

### 6.4 Арифметика, преобразования, вывод

- Переполнение `int` ловится через `__builtin_add_overflow`, `__builtin_sub_overflow`, `__builtin_mul_overflow`. Отдельно проверяются минимальный `int` / `-1` и `-x` от минимального `int`.
- `int(str)` и `real(str)` разбирают строку через `std::from_chars` и требуют, чтобы была прочитана вся строка. `from_chars` не принимает ведущий `+`, его нужно обработать отдельно.
- Печать `real`: `std::to_chars(first, last, value)` без формата и точности даёт кратчайшую запись, по которой значение восстанавливается однозначно. Если в результате нет `.`, `e`, `inf`, `nan`, дописывается `.0`.

## 7. Диагностика

### 7.1 Формат

```text
<файл>:<строка>:<столбец>: <этап> error: <сообщение>
```

- Этап — `lexical`, `syntax`, `semantic` или `runtime`. Сообщение — по-русски.
- Позиция — начало конструкции, к которой относится ошибка. В REPL вместо имени файла пишется `<repl>`, строки считаются внутри фрагмента.
- Вывод программы идёт только в стандартный вывод, диагностика — только в поток ошибок.

```text
demo.mfy:3:14: lexical error: незакрытый строковый литерал
demo.mfy:5:11: syntax error: ожидалось ';', получено '='
demo.mfy:7:5: semantic error: нельзя присвоить значение типа str переменной типа int
demo.mfy:9:12: runtime error: индекс 5 вне границ массива длины 3
```

### 7.2 Поведение этапов

| Этап | Поведение |
|---|---|
| `lexical` | первая ошибка останавливает обработку |
| `syntax` | первая ошибка останавливает обработку; сообщение перечисляет ожидаемые лексемы (§3.3) |
| `semantic` | выводятся все найденные ошибки по порядку позиций |
| `runtime` | первая ошибка останавливает программу |

## 8. Командная строка

```text
mfy tokens  <файл>
mfy ast     <файл>
mfy ast-dot <файл>
mfy check   <файл>
mfy run     [--seed N] <файл>
mfy repl    [--seed N]
```

| Команда | Этапы | Результат |
|---|---|---|
| `tokens` | сканер | список лексем (§8.1) |
| `ast` | сканер, парсер | дерево в текстовом виде (§4.2) |
| `ast-dot` | сканер, парсер | дерево в формате Graphviz DOT (§4.3) |
| `check` | сканер, парсер, проверка | при успехе ничего не печатает |
| `run` | все этапы, затем исполнение | вывод программы |
| `repl` | интерактивный режим (§9) | |

`--seed N` задаёт начальное значение генератора для `random` (README §14.9), по умолчанию 0.

| Код завершения | Значение |
|---|---|
| `0` | успех |
| `1` | лексическая, синтаксическая или семантическая ошибка |
| `2` | ошибка выполнения |
| `3` | неверные аргументы командной строки или файл не открывается |

### 8.1 Формат `tokens`

Одна лексема на строку: диапазон, вид (§2.3), текст лексемы как в исходнике. Последняя строка — `EOF`.

```text
1:1-1:3     LET       let
1:5-1:5     IDENT     x
1:6-1:6     COLON     :
1:8-1:10    INT       int
1:12-1:12   ASSIGN    =
1:14-1:14   INT_LIT   1
1:16-1:16   PLUS      +
1:18-1:18   INT_LIT   2
1:19-1:19   SEMI      ;
2:1-2:1     EOF
```

## 9. REPL

- Приглашение — `mfy> `, продолжение — `...> `.
- Строки накапливаются во фрагмент, пока скобки `()`, `[]`, `{}` не сбалансированы или последний значимый символ — не `;` и не `}`. Чтобы не считать скобки внутри строк и комментариев, накопленный текст прогоняется через сканер; незакрытая строка или комментарий тоже означают «читать дальше».
- Готовый фрагмент обрабатывается целиком: сканер, парсер, проверка в контексте сеанса, исполнение.
- Глобальные переменные, функции и структуры сохраняются между фрагментами. Функции фрагмента видят глобальные переменные из предыдущих фрагментов и из текущего. Глобальная переменная живёт до конца сеанса.
- **Атомарность.** Если во фрагменте возникла ошибка на любом этапе, состояние сеанса возвращается к тому, что было до фрагмента: объявления фрагмента отменяются, изменения существующих переменных откатываются. Перед исполнением фрагмента сохраняется копия значений глобального окружения; при ошибке значения записываются обратно в те же ячейки, чтобы старые указатели остались действительными. Уже напечатанный вывод и прочитанный ввод не возвращаются.
- Поскольку `}` в конце строки завершает фрагмент, `else` пишется на той же строке, что и закрывающая скобка `if`.
- Служебные команды: `:help` — справка, `:quit` — выход (также конец ввода, Ctrl+D).

```text
mfy> let x: int = 10;
mfy> def twice(n: int): int {
...>     return n * 2;
...> }
mfy> print twice(x);
20
mfy> x = x / 0;
<repl>:1:5: runtime error: деление на ноль
mfy> print x;
10
```

## 10. Расширения

Синтаксис и правила расширений — README §14. Здесь — как их реализовать.

- **Генератор сканера из регулярных выражений.** Лексика задаётся регулярными выражениями README §2. По ним своим кодом строится НКА (построение Томпсона), затем ДКА (построение подмножеств) и минимальный ДКА. В каждом принимающем состоянии запоминается вид лексемы с наивысшим приоритетом, поэтому правило самой длинной лексемы и приоритеты (§2.1) сохраняются.
- **Реактивные переменные.** Проверка строит граф зависимостей: вершины — реактивные переменные, рёбра — переменные из их выражений, по всем объявлениям и перепривязкам. Циклы ищутся обходом в глубину. При исполнении проще всего вычислять выражение при каждом чтении; пересчёт при изменении зависимостей тоже допустим.
- **Неинициализированные переменные.** Анализ потока данных на проверке: для каждой точки программы — множество переменных, которым точно присвоено значение. Слияние ветвей — пересечение множеств; тело цикла анализируется от состояния перед циклом.
- **`include`.** Множество канонических путей уже подключённых файлов — для однократного подключения; стек подключений — для поиска циклов. Каждая лексема хранит имя своего файла, чтобы диагностика указывала его.
- **`random`.** `std::mt19937_64 gen(seed)`, результат — `lo + gen() % (hi - lo + 1)`. Так значения совпадают во всех стандартных библиотеках C++ (в отличие от `std::uniform_int_distribution`). Разность `hi - lo + 1` считается в беззнаковом типе, чтобы не переполниться при `lo` и `hi` на краях диапазона.

## 11. Соответствие первой версии задания

Первая версия задания (PDF «Интерпретатор: групповой вариант задания») использовала другие названия. Таблица показывает, где каждое требование.

**Язык**

| Требование задания | В MFY |
|---|---|
| Типы `int`, `float`, `bool`, `string` | `int`, `real`, `bool`, `str` (+ `void`), README §4.1 |
| Ключевое слово `function` | `def`, README §8 |
| Тернарный оператор `cond ? a : b` | `cond -> a \| b`, README §6.10 |
| `++`, `--` | только префиксные `++x`, `--x`, README §6.5 |
| Переменные с явным типом `let x: int = 10;` | так же, плюс `let a, b: int = 0;`, README §7.1 |
| `print`, `if`/`else`, `while`, `for`, `break`, `continue` | так же; скобки у условия необязательны, тело — всегда блок, README §7 |
| `and`, `or`, `not` с коротким вычислением | так же, README §6.9 |
| Массивы: литерал, `a[i]`, `a[i] = v`, `length(a)`, выход за границы | так же, плюс многомерные `T[N1, N2]`, README §4.3 |
| Копируется ли массив при присваивании | да, глубоко, README §5.3 |
| Правила смешанных операций `int` и `float` | README §4.6 |
| Функции с типизированными параметрами, `return`, рекурсия | README §8 |
| Вложенные области видимости, затенение, повторное объявление | README §9 |
| Встроенные `input`, `length`, `int`, `float`, `str`, `bool`, `assert` | `input`, `length`, `int`, `real`, `str`, `bool`, `assert`, README §11 |
| Структуры: поля, создание, `obj.field`, запись в поле | `type`, `T(…)`, `s.f`, `p->f`, README §4.4 |
| Комментарии `//`, `/* */` | так же, README §2.2 |
| Сверх задания | указатели `p`, константы `c`, `&`, `$`, `->`, присваивание-выражение `:=` |
